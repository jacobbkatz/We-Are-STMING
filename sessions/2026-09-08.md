# 37. Repository hygiene: one value per fact, and a checker

Jacob: *"The github is getting quite complicated and convoluted... I'm happy with it if it is
optimized for your use."*

**Measured before changing anything.** 12,586 lines of prose across 34 markdown files. **Size is not
the problem** — nobody reads it end to end, it gets grepped. **Duplication is the problem**, and it
is measurable:

| Fact | Files repeating it |
|---|---|
| `37 nA` — **known wrong since 2026-09-07** | **13** |
| `4.096` as the full scale — **known wrong since 2026-09-07** | **14** |
| `±3 V` | 16 |
| `100 MΩ` | 20 |

**Both corrections were made yesterday and stale copies survived in six live documents.** That is
the actual cost of the sprawl, and it is the failure that has bitten this project hardest.

## What was built

**`docs/FACTS.md`** — the canonical value of every number that matters, with provenance and date,
plus a **RETIRED** table of superseded values. The rule is one value per fact: other documents link
here rather than restating.

**`Code/pc/check_facts.py`** — reads that RETIRED table and reports anywhere a retired value still
sits in a live document. It **skips `sessions/`**, because logs are history and must keep their
original numbers, and it skips lines that are deliberately quoting the old value. **Wired into the
SessionStart hook**, so it runs before any work starts.

It over-reports rather than under-reports, which is the right bias — but a checker that cries wolf
gets ignored, so it was tuned from 59 hits down to 12 real ones before the fixes.

## What it found

**A live code bug.** `Code/pc/stm_approach.py` still defaulted `--full-scale` to **4.096**, so the
one tool written to run an approach on real hardware would have reported every current **2.5 times
too small**. Nothing else had caught it. Now 10.24, and the 40 tests still pass.

**Six documents still asserting 119 nA as "37 nA"** — `CLAUDE.md`, `STATUS.md`,
`docs/ENGINEERING_REFERENCE.md`, `docs/OPEN_QUESTIONS.md`, `docs/UPSTREAM_BERARD.md` and the
handoff's own correction banner. All fixed.

**Stale derived figures**: "1 nA = 800 counts" (now 320), a ceiling of "40.96 nA" (now 102.4), the
signed-versus-unsigned argument still quoting +3.73 V (now +9.33 V differential), and
`UPSTREAM_BERARD`'s "roughly thirty thousand times the OPA627's bias current" (now **119,000**).

**Session logs were left alone.** They are the historical record and their numbers are correct for
the day they were written.

## What was deliberately NOT done

**`STATUS.md` was not trimmed**, despite being 863 lines. It is structured with clear headings and
is navigated by grep, not read whole. Restructuring it would risk breaking cross-references from a
dozen documents for a gain that is aesthetic rather than real. **The duplication was the problem,
not the length.**

**No documents were merged or deleted.** Each has a distinct job and the file map in `CLAUDE.md`
§6 says what it is.

## The rule, now in `CLAUDE.md` §3bb

> One value per fact. Do not restate a number from `docs/FACTS.md` elsewhere — link to it. When a
> value changes, change it there first, add the old one to the RETIRED table, run the checker, fix
> what it finds. Session logs keep their original numbers.

## One honest limitation

**Individual numbers still appear in prose across four or five documents.** `102.4 nA` is in
`STATUS.md`, `FACTS.md`, `ENGINEERING_REFERENCE.md` and `UPSTREAM_MECHPANDA.md`.

**That is deliberate and should stay.** There is a difference between a competing *register* — two
constants tables, which is a source-of-truth problem — and a number *cited in an argument*, which
is how prose works. Stripping every figure out and replacing it with a link would make the
documents unreadable, which is simplification for its own sake.

**The protection is the checker, not a prohibition.** When a value changes it goes in the RETIRED
table and `check_facts.py` finds every prose copy — which is exactly how the six stale copies of
"37 nA" were found. **What was eliminated is competing registers. Prose citations remain and are
now machine-guarded.**

## Process lessons

**A checker beats a rule.** Both of the values corrected yesterday had been corrected *by hand*,
and both left stale copies behind in six live documents. The rule "remember to update everywhere"
had already failed twice. `check_facts.py` found all six in under a second, plus a real code bug
nobody had looked for.

**The audit was worth doing before the changes, and worth arguing with during them.** Two of its
recommendations were wrong. Writing the assessment separately from the implementation is what made
them visible — had they been decided and executed in one pass, the cold-start procedure would have
been archived without anyone noticing it was the only one.

**Reliability over context savings.** `CLAUDE.md`'s numbered rules look like accretion and are not:
each is a distinct failure this project actually had, and ten documents cite the numbers. Compressing
them would have been tidying at the cost of the safeguards.
